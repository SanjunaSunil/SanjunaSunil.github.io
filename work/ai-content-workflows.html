The Problem

Repetitive tasks were eating writing time

Two recurring tasks consumed a disproportionate amount of writing time across the SAP User Assistance team: writing alt text for UI screenshots and drafting release notes from Jira tickets.

Alt text was often skipped entirely or written inconsistently. Writers defaulted to phrases like "Image of Report Center" — meaningless to screen reader users — or wrote verbose descriptions that buried the functional detail. There was no shared standard, no word limit, and no guidance on what to focus on.

Release notes required writers to read each Jira ticket, interpret engineering language, translate it into customer-facing copy, and reformat it into the SAP UA template — a slow, mechanical task repeated dozens of times per release across six release cycles a year.

Both tasks had clear inputs, well-defined outputs, and existing quality standards that could be encoded directly into a prompt — making them strong candidates for AI assistance.

The Process

Encoding standards into a reusable prompt

  • Role framing: Opened the prompt with an explicit role — "expert technical writer specialising in accessible, concise alt text for software documentation" — to prime the model for domain-appropriate output before any instructions were given.
  • Hard constraint on length: Set a 25-word maximum and present tense requirement. Most alt-text failures are caused by over-description; the word cap forces the model to prioritise the one functional detail that matters.
  • Explicit banned phrases: Listed the exact phrases that produce useless output — "image of," "screenshot showing," "displays," "shows," "displayed," "showing" — rather than saying "be concise." Negative constraints are more reliable than positive tone guidance.
  • Audience framing: Included the instruction "assume your audience relies on your description to understand or interact with the content" — reorienting the model away from visual description toward functional utility.
  • Multi-screenshot handling: Added a labelling convention (Screenshot 1: / Screenshot 2:) so the prompt scales to batch inputs without producing ambiguous output.
  • Testing & rollout: Validated across screenshot types — dashboards, dialogs, error states, configuration panels. Documented in Confluence with usage guidance and example outputs; adopted globally across SAP User Assistance teams.
The Outcome

Two templates, global adoption

Global Both prompt templates adopted across SAP User Assistance teams globally — the alt-text prompt became part of the standard authoring workflow for writers adding screenshots to documentation.
Consistent Alt text quality standardised across teams — WCAG-compliant descriptions replacing inconsistent or missing alt text across SAP product documentation.
Faster Release note drafting time reduced — writers provide Jira ticket data and receive a formatted first draft, reviewing and editing rather than starting from a blank template.
