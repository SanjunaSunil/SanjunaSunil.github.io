The Problem

A redesigned flow with new UX gaps

A sharing experience in SAP SuccessFactors was undergoing a redesign — new layout, new controls, new navigation patterns. UI text review was part of the process, but the review surfaced issues that went beyond copy: the redesign had introduced accessibility problems that needed design-level fixes, not just wording changes.

Two issues stood out. First, the keyboard focus order skipped the new header element — meaning users who navigate without a mouse would miss a key interactive control entirely, a direct WCAG failure. Second, the back navigation label was ambiguous: in the redesigned flow, the back button no longer returned to the expected previous screen, but the label gave no indication of where it would actually go.

Both issues were invisible during design — they only became visible when you read the interface the way a screen reader or keyboard user would, which is exactly what a UI text review is for.

The Process

Text review as accessibility signal

  • Reading the flow as a user: Walked through the redesigned sharing experience as a keyboard and screen reader user would — not just reading the copy, but testing the tab order and verifying that each control's label matched what it actually did.
  • Documenting findings with context: Flagged both issues with specific detail — which element was skipped, what the current back label said, what a user would expect versus what would actually happen. Framed as user impact, not just a list of mistakes.
  • Handing off to design: Shared findings with the design team with enough context that they could act without a separate meeting — clear screenshots, the expected behaviour, and the WCAG criterion involved.
  • Design response: The team used the back navigation finding as the starting point for a new header pattern — solving the problem in a way that could be reused across the product, not just patched in this one flow.
  • Pattern library contribution: Documented the new pattern and the reasoning behind it, helping the team build out the pattern library and giving future designers a reference for navigation patterns in redesigned flows.
The Outcome

A bug fix that became a design system contribution

New pattern The back navigation finding prompted the design team to create a new header pattern — a reusable component now available across the product, not just a local fix.
Documented The pattern and its rationale were added to the product's pattern library — a lasting reference for designers working on navigation in redesigned flows.
Accessible Keyboard focus order corrected before release — a WCAG failure caught during text review rather than in a separate accessibility audit.
